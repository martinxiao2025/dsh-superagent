# U6：来源增删启停 API、健康接口、面板交互与 i18n

## Context

来源已按记录（`Settings.sources[记录ID]`）建模，U6a/U6b 已完成多记录执行侧与资源路由。当前管理 API 只能修改既有记录的
`{ enabled, config }`，无法新增/删除记录；面板没有新增来源入口；也没有独立的健康探针接口。本单元补齐这些能力，并把
「删除/停用一条正在工作的记录」的后果定义成可验证的行为，而不是静默悬挂。

**本单元范围**：来源新增/删除 API、启用/停用（沿用现有 `PUT settings/:block`）、`GET health`、面板交互、简中/英 i18n。
**不做**：U7 的 404 加固、其他后续单元。

## 语义决定（必须可验证）

一条记录的身份是记录 ID；其「工作」由三部分组成：轮询/触发器、线程订阅、未完成工单。

- **停用（`enabled: false`）**：
  1. 保存后该记录不再通过 `SourceRegistry.scope()` 监听（返回 `source_disabled`），重启后部署里不再包含它；
  2. 以该记录主触发来源（`ticket.origin.triggerId` 对应 `trigger.source`）归属的**所有未结束工单立即结束**，
     `ended = { by: 'human', outcome: 'stopped', reason: 'source_disabled' }`，其派工一并停止；
  3. 历史线程与触发器**保留**（线程订阅关系作为历史保留，触发器仍在库中），不再产生新触发；
  4. `save` 结果新增 `stopped` 数量，面板在保存前提示将结束多少工单。
- **删除（`DELETE sources/:id`）**：
  1. 仍有未结束工单时**拒绝**，HTTP 409，`{ code: 'sourceInUse', values: { source, count } }`；
  2. 允许删除时：停止该记录轮询、移除 `settings.sources[id]` 与 `settings.policy.sources[id]`、释放健康项与同步重试、
     触发重启；历史线程/触发器保留。
- **新增（`POST sources`）**：
  - 只接受已安装的 `kind`；记录 ID 可选，缺省按 `kind`、`kind-2`… 生成；显式 ID 冲突则拒绝；
  - 配置用该 kind 的 schema 解析（缺省值生效），新记录默认 `enabled: true`，保存后重启；
  - 返回 `{ id, revision, restarting: true }`。

错误码新增：`sourceKindUnknown`（缺失 → 404）、`sourceExists`（400）、`sourceInUse`（HTTP 409，见 `failure` 映射）。

## 实现步骤

### 1. 核心错误与类型（`src/core/errors.ts`、`src/core/engine.ts`）

- `USER_ERRORS` 增加三条：`sourceKindUnknown`、`sourceExists`、`sourceInUse`（值均用 `{kind}`/`{source}`/`{count}`）。
- `EngineForSettings` 从 `Pick<Engine, 'policyChanged'>` 扩为 `'policyChanged' | 'stopTicket'`。

### 2. 设置领域逻辑（`src/app/settings.ts`）

- `SettingsHost.store` 的 Pick 增加 `'triggers'`（用于按主触发来源归属工单）。
- 新增公开方法 `openTickets(id)`：`store.tickets.open()` 中 `store.triggers.get(ticket.origin.triggerId)?.source === id`。
- 扩展 `save()`：
  - 记录保存前是否由启用变为停用（`kind === 'source' && current.sources[id]?.enabled !== false && parsed.enabled === false`）；
  - 保存成功后对该记录的 `openTickets` 逐个 `engine.stopTicket(id, 'source_disabled')`，返回 `stopped` 数量；
  - 其余行为（策略版本、重启、通知）保持不变。
- 新增 `createSource(kind, id, config, origin)`：
  - 校验 kind 已安装；生成/校验唯一 ID；`kind.schema.parse(config ?? {})`；
  - `store.saveSettings` 写入新记录（`source:${id}` 修订、通知主会话），`sources.syncHealth(next)`，`setup.restart()`。
- 新增 `removeSource(id, origin)`：
  - 记录不存在 → `UserError('sourceNotInstalled')`；有未结束工单 → `UserError('sourceInUse', { count })`；
  - 原子保存移除 `sources[id]` 与 `policy.sources[id]`，按策略版本变化通知引擎；
  - 清理 `sync:<id>` 健康条目与重试计时器（新增私有 `releaseSource`），`sources.syncHealth()`，重启。

### 3. API 契约与路由（`src/app/api.ts`、`src/app/http.ts`、`src/app/views/sources.ts`、`src/app/views/settings.ts`）

- `Api` 增加：
  - `'POST sources'`：body `{ kind: string; id?: string; config?: unknown }`，response `{ id; revision; restarting: true }`；
  - `'DELETE sources/:id'`：response `{ removed: true; restarting: true }`；
  - `'GET health'`：response 见下。
- `http.ts`：
  - `HttpHost.settings` Pick 增加 `createSource`/`removeSource`；
  - `routes(runtime, listen)` 增加三条路由；`listen` 来自 `ctx.webServer.host/port`；
  - `failure` 把 `UserError('sourceInUse')` 映射为 409（其余 UserError 规则不变）；
  - 新增 `healthView(runtime, listen)`：`{ ok, stage: 'ready'|'setup', configured, paused, problem, listen, machine: { stateDir }, sources }`；
    `sources` 复用 `sourceHealth` + 新导出的 `sourceState`（`src/app/views/sources.ts`），输出 `{ id, kind, enabled, installed, state, health }`。
- `views/settings.ts`：每个来源增加 `openTickets` 计数；顶层增加 `kinds`（来自 `SourceRegistry.kindsList()`，只含已安装类型的
  `{ kind, title, description }`）。

### 4. 面板（`src/client/source.tsx`、`src/client/locales.ts`）

- `SourceSettings` 顶部新增「新增来源」区块（不使用 `.dt-card`，避免改变既有卡片数量断言）：
  - 类型下拉（`settings.kinds`）、可选记录 ID 输入、「新增来源」按钮；
  - 调用 `POST sources`，成功 toast「已新增来源 {id}，请补全配置后保存」并 `reload()`。
- `SourceCard` 头部新增删除按钮（`ConfirmButton`，`trash` 图标）：
  - 无未结束工单：确认文案说明「轮询立即停止、策略部分移除、历史线程与触发保留」；
  - 有未结束工单：确认文案直接说明不能删除及数量，点击后展示服务端 409 的本地化错误；
  - 成功后 toast「已删除来源 {name}」并 `reload()`。
- 停用提示：当开关由开变关且 `openTickets > 0`，`SaveBar` 状态显示「停用会立即停止轮询，并结束 N 个未完成工单
  （按“来源已停用”记录）。线程与触发保留。」（优先于重启提示）。
- `locales.ts` 新增上述 UI 文案与 `userError.sourceKindUnknown`、`userError.sourceExists`、`userError.sourceInUse`。

### 5. 面板测试夹具（`tests/fixtures/panel-server.ts`）

- 新增 `openTickets: Record<string, number>` 与对应 `GET settings` 的 `openTickets`/`kinds` 字段。
- 实现 `POST sources`（按 kind/`kind-2` 生成并写入 `server.settings.sources`）、`DELETE sources/:id`（有未结束工时返回 409、
  否则移除）、`GET health`（占位响应）。
- `sourceSettings()` 改为遍历 `server.settings.sources` 并按 ID 排序，使新增/删除能真实反映在面板上。
