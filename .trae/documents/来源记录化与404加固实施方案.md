# 来源记录化与 `/orchestrator` 404 加固实施方案（全新重构版）

## Context

当前 dsh-superagent 把「来源」建模成插件开关：`github-watch` / `gitlab-watch` / `feishu-watch` 各是 bundle 里的一条插件条目，`Settings.sources` 以类型名（`github`/`gitlab`/`feishu`）为键，每种类型只能有一个实例；GitLab、飞书默认 `disabled: true`，只能改 profile 的 `cordis.patch.yml` 启用。这与「来源是用户数据」的目标冲突。

同时桌面版存在偶发缺陷：`/orchestrator` 前缀整体未注册（空体 404），侧栏仍显示 Superagent，同构建同配置出现过 4 次。已排除配置、等待时间、端口、残留进程、stateDir 锁、patch 位置。

**口径变更（以最新指令为准）**：不做旧数据迁移，按全新重构来。删除旧的单来源配置模型、bundle 开关式启停、为兼容旧配置而设的分支和补丁位置约定；新记录模型直接定型，不做双写、不做过过渡壳、不写迁移代码；测试与文档中描述旧模型的部分同步改成新模型，不留「仅为兼容」的说明。之前计划中的迁移单元取消。

目标：来源成为可增删改启停的记录列表，同类型可多条并存；适配器注册表保留；`/orchestrator` 404 根因修复或给出可复现条件与诊断手段。界面文案、注释、文档全部简体中文，UTF-8 无 BOM。

## 一、核心设计

### 1. 来源记录模型（唯一事实来源）

```ts
// Settings.sources：键为记录 ID
type SourceRecord = {
  kind: string       // 适配器类型：github / gitlab / feishu / 未来扩展
  enabled: boolean
  config: {
    instanceUrl: string   // 实例地址；空 = 官方站点
    cli: string           // 凭据引用：已登录的 CLI 包装/命令名
    // 以下由各适配器 schema 定义
    repository?: string   // GitHub：owner/name
    project?: string      // GitLab：group/project
    // 轮询与过滤参数（各适配器字段，如 streams/authors/labels）
    [key: string]: unknown
  }
}
```

- 记录 ID 规则 `^[a-z][a-z0-9-]*$`，全仓唯一；`POST` 创建时由服务端生成（`kind`、`kind-2`…）或校验客户端提供的 ID。
- 记录是唯一事实来源：适配器不再从插件条目读取任何配置。新增类型只需新增适配器并在内置适配器清单登记，核心流程不变。
- 凭据沿用现有机制：`cli` 指向已登录的 `gh`/`glab`/`lark-cli` 包装或命令，登录态由 CLI 自身持有；不新增明文存储。实例地址通过 `GH_HOST` / `GITLAB_HOST` 传递给 CLI。
- **无默认记录、无主记录**：所有记录地位相同；首次使用由面板创建。

### 2. 适配器内置化（删除来源插件开关）

- `src/index.ts` 主插件直接注册内置适配器（`github`/`gitlab`/`feishu`），Runtime 初始化后启动多记录轮询。
- `cordis.patch.yml` 只保留 `dsh-superagent` 与两个会话预设，删除 `dsh-superagent-github` / `-feishu` / `-gitlab` 三条 `insert` 及 `disabled` 约定。
- 删除 `package.json` 的 `./github-watch`、`./feishu-watch`、`./gitlab-watch` 导出与 tsdown 对应入口；适配器改为普通模块导出 `SourceAdapter = { kind: SourceKind; watch(host): Promise<void> }`。
- 文档删除「启用可选来源需修改 profile patch」的说明；来源只通过面板/管理 API 管理。

### 3. 身份统一：记录 ID 即来源身份（无兼容分支）

| 位置 | 新规则 |
| --- | --- |
| `trigger.source` / `channel.source` | 记录 ID |
| `policy.sources` 键 | 记录 ID |
| 线程键 | `<记录ID>:<类型内后缀>`，如 `github-2:issue:12`、`gl-1:mr:7` |
| 触发器去重 ID | `key('<记录ID>-issue', n)` 等，天然按记录隔离 |
| KV 键 | `github-stream:<记录ID>:<stream>`、`gitlab-cursor:<记录ID>:<stream>`、`source-labels:<记录ID>` |
| 健康项 | 首个声明名用 `<记录ID>`，其余 `<记录ID>:<name>`（如 `f1:history`） |
| 环境变量 | `DSH_SUPERAGENT_SOURCE_<ID>_<FIELD>`（ID 大写、`-` 转 `_`），另有 `DSH_SUPERAGENT_SOURCE_ID` / `_KIND` |

集中实现 `src/sources/identity.ts`：`threadKey`、`triggerKey`、`kvKey`、`healthNames`、`envKey`。所有身份拼接只走这里，禁止散落字符串拼接。

### 4. 全局删除旧模型

- `src/policy.ts`：`SourceInstanceSchema` 加必填 `kind`；删除按类型名生成默认实例的逻辑；`SettingsBlock` 仍为 `source:<记录ID>`。
- `src/app/migration.ts`：删除旧扁平设置 → `sources.github/feishu` 的转换与 `REMOVED_SOURCES` 兼容分支；只保留与来源无关的 schema 版本处理。旧格式数据不再识别（按最新口径接受重置）。
- `src/app/setup.ts` / `src/deployment.ts`：删除 `settings.sources.github/feishu/gitlab` 的单来源读取；`SETUP_FIELDS` 改为按类型字段表。
- `src/sources/registry.ts`：删除 `resolve()` 中 `id = kind.kind` 的单实例假设。
- 测试与文档同步删除「旧配置可迁移」「主记录沿用旧键」等描述。

### 5. 校验与错误

- 记录级校验失败只影响该记录：`enabled` 不被静默改写，运行时把可读原因写入该记录 `problem`（字段路径 + 中文原因），该记录暂停轮询，其他记录继续。
- API 错误统一形状：`{ error: string, issues?: { path, message }[] }`；覆盖重复 ID、未知类型、非法 ID、缺少必填、实例地址非法、凭据 CLI 不可用。
- 删除保护：有未结束工单（open/claimed/running）的记录拒绝删除并说明数量；删除时释放健康项、停止该记录轮询、清理其策略部分，保留历史线程与日志。

### 6. 部署解析与运行态

- `Deployment` 改为 `Machine + sources: Record<记录ID, ResolvedSource>`；删除 `repository/github/feishu/gitlab` 顶层单来源字段，所有消费者按记录解析。
- `Setup` 逐记录解析：每种类型独立探针；失败只标记该记录 `problem`。运行时不再因某一个来源不可用而整体未就绪；机器级环境（git/shim）照常初始化。
- 实例地址映射：GitHub Enterprise → `GH_HOST`；自建 GitLab → `GITLAB_HOST`；链接生成使用记录实例地址。官方站点保持默认。
- 环境变量按记录生成；变量声明清单与提示词同步展示，不再有按类型固定的变量名。

### 7. 适配器多实例

- 每个适配器持有一个 AbortController；按记录枚举，每条记录独立游标、健康项、失败计数与下次轮询时间；单记录失败不阻塞其他记录。
- `SourceContext` 按记录作用域化：`ctx.instance`（记录 ID）、`ctx.source`（该记录解析结果）、`ctx.config()`（该记录配置）、`ctx.commands`（绑定该记录 CLI 与实例地址）、`ctx.report()`（映射到该记录健康项）。
- 出站 `send` / `link` / `threadContext` 一律通过 `channel.source`（记录 ID）解析记录与对应部署，避免回复到错误仓库或错误账号。
- 轮询调度不引入新框架：每条记录记录 `nextAt`，适配器按最短到期时间唤醒；禁用/删除后不再调度。

### 8. 管理 API 与面板

保留：
- `GET /orchestrator/api/settings` → 记录卡片 + `kinds` 类型目录（title/description/fields/defaults）。
- `PUT /orchestrator/api/settings/source:<id>` → 更新 `{ enabled, config }`（含启停）。
- `GET /orchestrator/api/sources` → 运行状态。

新增：
- `POST /orchestrator/api/sources`，body `{ kind, id?, config? }` → `201 { id }`；校验失败 `400` + issues。
- `DELETE /orchestrator/api/sources/:id` → `204`；有未结束工单 `409` + 可读原因；不存在 `404`。

面板：
- 来源页顶部「新增来源」：选择类型 → 显示该类型字段（实例地址、凭据引用、仓库/项目、轮询与过滤）→ 创建。
- 每张卡显示记录 ID、类型、实例地址、启停开关、删除（二次确认），校验失败在卡内展示原因。
- 新增中英文案；空 404 时显示诊断提示（stateDir、启动记录、健康接口地址）。

### 9. `/orchestrator` 404 加固

根因候选（按可能性）：
1. `registerHttp` 仅当 `ctx.webServer.host === '127.0.0.1'` 才注册；宿主为 `localhost`/`0.0.0.0`/IPv6 时在注册前抛错，`runtime.ready` 拒绝。
2. `apply` 在注册后 `await runtime.ready`；初始化任一步骤抛错 → apply 拒绝 → Cordis 回收插件 effect → 已注册前缀被卸载。

修复：
- 注册不再以 host 为条件；改为请求时校验 Host 白名单 + 同源头，非回环请求返回 403。
- 初始化任何步骤都不允许在 HTTP 注册前抛错；`apply` 不再因初始化失败而 reject，失败写结构化日志与启动记录，前缀保持挂载。
- 启动阶段记录 `stateDir/startup.json`（pid、port、host、构建版本、阶段、错误栈、时间戳），上一份保留为 `startup.prev.json`。
- 新增 `GET /orchestrator/api/health`：插件是否注册、初始化阶段、失败原因、监听端口/host、各记录健康摘要。
- 面板在空体 404 时显示诊断提示，不再只显示空白。
- 桌面验证：连续启动 ≥5 次，记录每次健康接口、侧栏、启动记录；若仍复现，按阶段字段定位并追加修复；若不复现，给出观测值、复现条件与剩余风险。

## 四、取舍与风险

- **全新重构**：不保留旧配置兼容层；升级后旧来源配置不再生效，需在面板重新添加。这是最新口径的明确取舍，文档会写明。
- **适配器内置化**：去掉来源插件开关，才真正满足「面板可操作、不改配置」；子路径插件与 bundle 条目一并删除，不留空转壳。
- **不做明文凭据存储**：继续用 CLI 登录态；企业实例通过 `GH_HOST`/`GITLAB_HOST` 选择实例。若某实例需要独立凭据，用户配置独立 CLI 包装并通过 `cli` 引用。
- **轮询隔离**：按记录独立游标与错误状态；同一适配器内共享唤醒循环，单记录失败不阻塞其他记录，不引入新调度框架。
- **删除保护**：有未结束工单的记录禁止删除，避免历史与出站消息悬挂。
