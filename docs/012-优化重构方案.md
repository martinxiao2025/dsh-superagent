## 一、背景与目标

dsh-superagent 是运行在 DSH（DeepSeek Harness）宿主上的双角色（orchestrator/worker）编码智能体编排插件：主会话做准入评估与路由，每工单一个 worker 会话在独立 git worktree 里完成软件开发全流程。

本次重构目标（按用户要求，不考虑数据迁移与旧数据兼容）：

| # | 目标 | 现状差距（已勘察定位） |
|---|------|----------------------|
| 1 | 标准、准确、高效 | 7 处旧数据兼容死代码；Windows 引号/路径规则 3–4 份拷贝；68 行 JS 字符串内嵌；runtime.ts 570 行组合根过重；二进制 xlsx 台账无法 diff/review |

## 二、勘察结论与宿主机制边界

### 2.1 关键技术可行性（均已读源码验证）

- **每请求模型覆盖**：`agent/request` 是 waterfall 事件，监听器每请求可改写 `LlmCallConfig`（dsh-agent runtime-types.ts:374）。现 `role-models.ts` 的 `system-prompt/assemble` + `agent/request` 双钩子先例只在首请求生效（`initial` 标志），扩展为按阶段每请求应用可行。
- **usage 采集**：`session/event` 监听器已存在（`src/app/sessions.ts:135`，现供 RetryHealth 用）；`assistant/message` 事件携带 `usage?: TokenUsage { inputTokens, outputTokens, totalTokens?, cacheReadTokens?, cacheWriteTokens?, reasoningTokens? }`（计数不相交：billed input = input + cacheRead + cacheWrite）；子代理会话经 `header.parentSession` 父链（sessions.ts:359 `limitSubagent` 已有 8 层回溯先例）可归因到工单。
- **宿主 workspace**（第 5 条的物理原语）：宿主 UI 唯一分组原语是 workspace（目录记录：id/path/title + 会话成员），侧边栏按 workspace 分组（dsh-client-ui-workspace tree.ts `groupByWorkspace`，扁平无嵌套）。
  - `workspaceRegistry.create(path, title?)` 幂等（同 canonical path 复用，title 仅创建时生效，重复调用不改已有 title）；`Workspace.setTitle / attachSession / detachSession / insertSessionBefore`；`registry.get / list / delete`（delete 保留目录与全部会话日志）。
  - **硬约束**：成员校验要求会话 cwd 与 workspace 路径**完全相等**（dsh-workspace entity.ts:139，子目录拒绝；attach 时 `cwd !== record.path` 直接抛错）。
- **master 会话**：id=`orchestrator-<stateDir key>`，cwd=stateDir（`src/app/runtime.ts:205,437`）。
- **存储**：`SCHEMA_VERSION=14` 一次性拒开旧库（`src/app/store.ts:83-85`），升版即重置，天然无迁移包袱。

### 2.2 第 5 条的实现边界（重要）

"工单会话（cwd=各自 worktree）全部收进单一项目 workspace"在宿主当前模型下**不可行**（cwd 必须等于 workspace 路径，worktree 各不相同）。采用**分层自动归类**：

1. 每项目自动建**项目 workspace**（宿主 UI 的"项目"节点）→ 汇聚项目根目录下的人工会话；
2. 每工单 workspace 统一命名 `<项目> · <工单标题>` → 同项目工单在宿主列表前缀聚拢、搜索直达；
3. 插件面板内完整"项目→工单→会话"树（完全可控）+ 深链跳宿主。

## 四、设计总览

```
阶段化执行（新）                    计量与预算（新）                自我升级闭环（新）
investigate→design→implement→      usage 归因（含子代理父链）       usage × 工单结果 × 修订版本
verify→review→deliver              → usage 表 → 两档预算闸          → retrospective 聚合报告
每阶段：模型自由配置 + 聚焦prompt     → 面板用量视图                  → master 经版本化工具落地改进
   ↑ orchestrator_stage 工具切换                                   → 再度量（闭环）

宿主项目集成（新）
项目启用 → 自动建宿主 workspace（title=项目名）→ 项目人工会话归类其下
工单启动 → 工单 workspace 命名「项目 · 工单」→ 工单 GC 时注销该 workspace
面板：项目→工单→会话树 + 深链宿主
```

设计原则：

- 阶段集固定六个规范枚举（investigate/design/implement/verify/review/deliver），**模型映射自由**（`models.stages` 每阶段 provider/model/reasoningEffort）；阶段前进不强制、只记录时间线（准确性靠聚焦提示词，不靠硬状态机）。
- **零配置零行为变化**：未配置阶段模型时回落 `models.worker` / `models.orchestrator`，与现状等价。
- **自我升级安全边界** = 行为配置（prompt/技能/模型/预算），版本化+可回滚+热加载；不做任意代码自改。
