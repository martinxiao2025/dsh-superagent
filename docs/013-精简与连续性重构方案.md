## 一、背景与目标

用户对 012 收官后的代码再做一轮「反复分析、对照业界最佳实践、持续优化重构」，聚焦三点：

1. **框架精简**：清除冗余设计与死代码——012 之后的代码面上仍存在零引用导出、无消费者的领域事件、
   永远拼不出的 locale 键、多份拷贝的同一逻辑。
2. **LLM 执行连续性**：012 §M2.5 规划的三项 token 基线瘦身（admission 详述迁技能、评估读缓存按
   threadKey 复用、transcript 进 TextCache）在 M2 执行记录中**被静默遗漏**（无完成/改设计/不采纳记录），
   本轮补齐；同时补上预算硬档停止对 worker 的「静默截断」——worker 收不到任何解释。
3. **不考虑数据迁移与旧数据兼容**（沿用 012 决策 1；SCHEMA 保持 15，本轮不动存储）。

勘察方式：四路并行全库审计（src/app 与根模块、src/client、core/task-sources/sources/executor、
prompts 与 LLM 连续性链路），所有「零引用」结论均经全仓（src+tests）grep 全词引用计数验证。

### N1 LLM 执行连续性与 token（012 M2.5 补课 + 连续性补洞）

| # | 内容 | 语义 |
|---|---|---|
| 1.1 | **admission 详述迁技能**：`prompts/admission.md` 保留「评估入口」「不可信数据与意图」两段 + 指引；其余五段（规则匹配/方向判定/视觉反馈/混合反馈/工单范围与读取）迁为内置技能 `admission`（仅注册给 orchestrator）。orchestrator 每请求固定提示词 14.5k 字符 → 约 12.5k（admission 段占 ~21% → ~8%）；评估细节只在真正评估时经 `skill` 工具按需进入上下文 | 保持 `runtime/admission` 部件键与团队覆盖兼容；新部件 `skill/admission` 可被团队覆盖 |
| 1.2 | **评估读缓存按 threadKey 复用**：`MasterAssessor` 增加线程级缓存（线程窗口 + 已载消息/游标，TTL 10 分钟、容量 8 线程）；评估超时重排（≤2 次）与宿主重启后同线程新 evalId 直接复用，免 `seed()` 全量重拉 | 缓存只含不可变线程历史；快照/图片引用仍按 evalId 隔离 |
| 1.3 | **transcript 进 TextCache**：`ticket/<id>/transcript` 与 `message/<n>` 的原始事件按 `${worker 会话}:transcript` 存入既有 `host.pages`（4M LRU）；runtime 订阅 `session/event` 到达即失效 | 事件未变期间重复读取零重拉；长工单排查与 worker 自读成本大幅下降 |
| 1.4 | **预算硬档解释注入**：`enforce()` 硬档路径在工单结束后向 worker 会话注入一次 `{budget_hard: true, detail}`（requestId `budget-hard:<ticketId>` 幂等、不唤醒）——worker 会话被人继续时，模型知道回合为何被取消、工单为何 ended，而不是只见 guard 拒绝文案 | 与软档同型；注入发生在结束事务提交之后，不被 `keepInbox:false` 清除 |

## 三、明确不采纳（避免过度收敛）

- `scheduler-{dispatch,reconcile,writeback}` 的 Context 门面合并——刻意的拆分设计，单实现是门面本身的意图。
- `notices.changedPaths` 与 `settings-history` 两套 diff 引擎合并——消费方与输出形态不同（主会话通知 vs 面板历史）。
- `views/*` 与 `resources.ts` 两条投影族合并——模型紧凑卡与 UI 全量视图是有意的分层（011 R 组评审确认）。
- 仅同文件使用却 export 的约 45 个符号降级私有——收益低且与「显式 API 面」风格冲突，只处理确认为死的导出。
- `later.ts` 叶子文件合并回 `effects.ts`——为断模块环独立成叶有明确评审编号（011 §9.2-3），保留。

## 四、风险与对策

| 风险 | 对策 |
|---|---|
| admission 迁技能改变主会话评估行为 | 核心段保留「评估前先打开 dsh-superagent-admission 技能」的强指引；`runtime/admission` 部件键不变，团队覆盖不受影响；prompt 相关既有测试全量回归 |
| threadKey 缓存读到过期线程内容 | 只缓存不可变历史（窗口消息/游标）；TTL 10 分钟 + 容量 8；新消息到达不清缓存（历史不变），仅时间淘汰 |
| transcript 缓存与事件流不一致 | 失效钩子挂在 `session/event`：任何该会话事件到达即删键；读侧 0 偏移未命中才拉取 |
| 删除 locale 键/导出漏改引用 | 全部结论先经全仓 grep 验证；每批跑 `pnpm check`（typecheck 先拦截） |
| CRLF 陷阱（历史 blob CRLF + autocrlf） | 只用 Edit 局部替换；新文件一律 LF；提交前抽查 diff 行数 |
