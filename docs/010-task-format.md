# 010 任务清单格式规范（标准工作簿与知识库任务表）

> 状态：已实现（0.2.0：`src/task-sources/excel-format.ts`、`excel-template.ts` 与 `GET task-format/template`），配套 [009-authoritative-project-design.md](009-authoritative-project-design.md) 第 6 章；第 7 节记录已定案的取舍。
> 适用范围：Excel / CSV / TSV 任务清单，以及飞书知识库中承载任务的文档与多维表格。
> 结论先行：**由系统定义标准格式，并作为唯一路径**；非标准清单整批拒绝，用模板改造。理由见第 1 节。

## 0. 为什么需要标准格式

现状是「列名靠用户填、缺列靠报错、格式靠约定」：`importTasks` 在缺编号列或标题列时直接抛错（[tasks.ts:55-88](../src/task-sources/tasks.ts#L55-L88)），但没有版本、没有模板、没有可选列语义，也无法区分「格式不对」和「内容不对」。这带来三个具体成本：

1. 每个项目各自发明表头，任务来源无法复用校验与提示。
2. 加一列（负责人、验收标准）就要改 schema 与表单。
3. 飞书文档与 Excel 走两套隐式约定，解析结果不可比。

标准格式把「结构契约」固定下来，把「业务列」留给模板与版本号扩展；自定义映射保留，但不再是主路径。

## 1. Excel 标准工作簿

### 1.1 文件与工作表

| 项 | 规则 |
| --- | --- |
| 扩展名 | `.xlsx` 为默认；`.csv` / `.tsv` 允许，等价于只有 `tasks` 一张表 |
| 任务表 | 工作表名 `tasks`（大小写不敏感）；缺少该表时回退到第一张表并给出警告 |
| 元数据表 | 工作表名 `_meta`，可选；只读，不参与任务解析 |
| 其他表 | 忽略，但在校验结果中列出「已忽略 N 张表」 |
| 编码 | `.csv` / `.tsv` 必须 UTF-8（含 BOM 可接受）；其他编码报错并提示转码 |

### 1.2 表头与列

第 1 行为表头，列名使用固定英文键（不随界面语言变化）。必填列缺失即整表拒绝。

| 列名 | 必填 | 类型 | 说明 |
| --- | --- | --- | --- |
| `task_id` | 是 | 文本 | 业务编号，表内唯一且不可变；改名视为新任务 |
| `title` | 是 | 文本 | 标题，非空 |
| `status` | 是 | 枚举 | 见 1.3；决定是否进入待处理集合 |
| `description` | 否 | 文本 | 描述，可含换行 |
| `priority` | 否 | 枚举 | 见 1.3；缺省按项目默认 |
| `owner` | 否 | 文本 | 负责人，仅展示与筛选，不参与调度 |
| `acceptance` | 否 | 文本 | 验收标准，注入任务上下文 |
| `depends_on` | 否 | 文本 | 依赖的 `task_id`，逗号分隔；仅记录，暂不阻塞调度 |
| `tags` | 否 | 文本 | 逗号分隔标签 |
| `updated_at` | 否 | 文本 | ISO 8601；用于增量判断，缺失不报错 |

规则：

- 列顺序无关，按列名匹配。
- 未知列忽略并计入警告，不报错。
- 表头重复列名直接报错并定位到列。
- 单元格一律按文本读取；数字型 `task_id` 统一转字符串，避免 `1` 与 `1.0` 不一致。

### 1.3 枚举与映射

| 字段 | 允许值 | 默认映射 |
| --- | --- | --- |
| `status` | `todo` / `in_progress` / `blocked` / `done` / `cancelled` | `todo`、`blocked` → 项目 `pendingStatuses`；`done` → `doneStatus`；`cancelled` → 取消；`in_progress` 默认不重新入队 |
| `priority` | `P0` / `P1` / `P2` / `P3` | 仅排序权重，P0 最高 |

- 枚举大小写不敏感，写入时规范化为小写 / 大写。
- 项目可在 `taskPolicy` 覆盖状态映射，但只能用上述枚举作为输入，不允许自定义新词。
- 枚举值非法 → 该行错误，整表拒绝（不静默跳过，避免任务凭空消失）。

### 1.4 版本化

`_meta` 表固定两列 `key` / `value`：

| key | 示例 | 说明 |
| --- | --- | --- |
| `schema_version` | `1` | 主版本号，必填；缺失按 1 处理并警告 |
| `generator` | `dsh-superagent/0.9` | 生成模板的工具版本，可选 |
| `updated_at` | `2026-11-11T10:00:00+08:00` | 整表更新时间，可选 |

版本规则：

- 新增可选列、放宽校验 → 主版本不变。
- 删除或重命名必填列、改变枚举集合、改变 `task_id` 语义 → 主版本 +1。
- 读取到高于当前支持的主版本 → 拒绝并提示升级插件，不做「尽力解析」。
- 读取到低于当前版本 → 按已发布规则兼容读取，不写回、不改文件。

### 1.5 多工作表与文件定位

- 项目内的 Excel 任务来源只能指向一个文件；文件必须是仓库内相对路径（如 `docs/backlog.xlsx`），随项目仓库同步。
- 文件不存在、被移出仓库、被 `.gitignore` 忽略导致同步缺失 → 校验失败并提示「文件不在仓库工作副本中」。
- 不在仓库内的绝对路径仅供本机调试，不作为生产形态（与 009 的「一项目一仓库」一致）。

## 2. 飞书知识库任务表

飞书侧不要求 Excel 文件，但要求**同一套列契约**：

- **文档（docx）**：文档内包含至少一张 Markdown 表格，表头包含 `task_id`、`title`、`status` 三列即视为任务表；可有多张任务表，按出现顺序拼接。
- **多维表格（bitable）**：字段名与列契约一致；一条记录一个任务，记录 ID 作为 `record_id`。
- **其他节点**（文件夹、快捷方式、普通文档）：文件夹递归展开；快捷方式解析到目标节点；无任务表的文档跳过，并在校验结果中列出。
- 文档内的复选框列表不再作为默认任务来源；仅当文档没有任务表且项目显式开启「清单模式」时才解析。

与 Excel 的差异只有载体，列的必填/可选、枚举、稳定键规则完全共用第 1 节。

## 3. 任务标识与稳定键

```
taskKey = <sourceKey>:<externalId>
sourceKey = excel:<projectId>:<repositoryPath>       // Excel
          = feishu:<nodeToken>                        // 知识库文档
          = feishu-bitable:<nodeToken>:<tableId>      // 多维表格
externalId = task_id（文档/表格内唯一）或 record_id（多维表格）
```

规则：

- `task_id` 在单个文档/表内唯一；跨文档重复视为不同任务，不做隐式去重。
- 若开启严格模式，同一 `task_id` 出现在多个文档中时整次同步拒绝，并列出冲突文档。
- 文档改名、移动目录不改变 `nodeToken`，任务键不变；文档被删除后重建会生成新 `nodeToken`，旧任务按「消失」处理。
- 任务消失：标记 `cancelled` 并保留历史；重新出现时按新任务入队一次。

## 4. 校验与模板

### 4.1 校验项

`POST task-sources/verify`（字段级预检，`field` 缺省为 `all`）按同一套规则输出：

| 检查 | 失败码 | 说明 |
| --- | --- | --- |
| 文件/节点可达 | `taskFileUnreadable` / `knowledgeBaseUnreadable` | 路径、权限、网络 |
| 表/节点归属 | `knowledgeBaseMismatch` | 节点不属于所选空间 |
| 标准表头完整 | `taskHeaderMissing` | 缺必填列，列出列名 |
| 版本支持 | `taskSchemaUnsupported` | 主版本过高 |
| 行级错误 | `taskRowInvalid` | 空 ID、重复 ID、非法枚举，带行号 |
| 解析结果 | — | 返回 `tasks`、`skippedDocs`、`warnings`、`durationMs` |

校验必须真实读取内容并返回条数，不允许只检查文件存在。

### 4.2 模板与自动初始化

- 面板「下载模板」通过 `GET task-format/template` 生成工作簿：`tasks`（表头 + 必填列）、`_meta`（`schema_version=1`）；没有单独的 CLI 命令。
- 模板不预填业务数据；示例行在校验时会被识别为普通任务，因此默认注释掉（放在 `_meta` 的 `example` 键里）。
- **清单缺失时自动创建初始版本**：字段验证与首轮轮询发现仓库中没有清单文件时，按扩展名写标准模板（`.xlsx` 用完整模板工作簿，`.csv`/`.tsv` 写全部标准表头行）并提交进工作副本，项目从验证或第一次轮询起就可用。

## 5. 边界处理

| 场景 | 处理 |
| --- | --- |
| 多工作表 | 只读 `tasks`；其余忽略并警告，`_meta` 保留 |
| 空行 / 全空行 | 跳过，不报错；行号仍按物理行计 |
| 重复 `task_id` | 整表拒绝，列出所有冲突行号 |
| 非法枚举 | 整表拒绝，定位到行与列 |
| 空表（只有表头） | 视为 0 条任务，警告「当前没有待处理任务」，不视为错误 |
| 并发编辑 | 每次轮询按文件哈希判断变化；哈希不变不重复解析 |
| 文件被 Excel 占用 | 读取失败按一次轮询失败处理，退避后重试；连续 N 次失败在项目详情告警 |
| 列被重命名 | 视为缺列，整表拒绝并给出「期望列 / 实际列」对照 |
| 多维表格字段改名 | 同上；记录 ID 不变则任务键不变 |

## 6. 非标准格式

自定义列映射与工作表选择已移除：Excel 任务来源只接受标准格式（`tasks` 表 + 固定表头 + 固定枚举）。非标准清单在校验与轮询中整批拒绝，错误信息指明缺失或非法的列与行号；改造路径是下载模板（`GET task-format/template`）重建清单。历史自定义映射配置随 0.2.0 的重置基线一并作废。

## 7. 已定案的取舍

1. **标准格式是唯一路径**（自定义映射已移除，不再有高级开关）——009 §13.1 第 10.13 项随此更新。
2. **`status` 就用这五个值**（`todo` / `in_progress` / `blocked` / `done` / `cancelled`，见 `excel-format.ts` 的 `TASK_STATUSES`）；未引入 `review`，需要验收语义时由 `taskPolicy` 的状态映射表达。
3. **`depends_on` 仅作元数据列**，不参与调度阻塞（调度器不读取该列）；引入依赖调度前不改变这一语义。
4. **清单模式不做**：复选框解析（原 `feishu-doc.ts` 的 `checklistTasks`）从未接线为可用路径，已随该文件的删除一并移除；任务只来自标准任务表与多维表格。
5. **模板生成只在面板**（`GET task-format/template`），不做 CLI 命令。
6. **严格模式默认关闭**：跨文档 `task_id` 默认按文档隔离（见 009 §13.1 第 10.12 项），严格模式留作可选。
