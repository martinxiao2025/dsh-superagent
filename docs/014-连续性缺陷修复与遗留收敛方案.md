## 一、背景与目标

第三轮「反复分析、对照业界最佳实践、持续优化重构」。勘察方式沿用前两轮：四路并行全库审计
（src/app 与根模块 / src/client / 数据面与执行器 / 提示词与 LLM 连续性链路），全部「零引用」结论经
全仓（src+tests）grep 全词引用计数复核；本轮另对照宿主 API 源码（`@deepseek-ai/dsh-api-session-controller`、
`dsh-system-prompt`）核验了分页默认值与提示词组装语义。

聚焦四点：

1. **LLM 连续性实锤缺陷**：transcript 读取忽略宿主 `hasMore`（默认 50 条窗口，长工单静默截断且模型无感知）；
   usage 资源主会话分页数学错误（offset>0 永远返回最新一页）；飞书 HTTP 传输无 per-call 超时（单个半开
   连接可静默冻结回写通道）；worker 会话被外部删除重建后缺失原始任务上下文；UsageMeter 两处无界内存增长。
2. **013 N2 批次遗漏还债**：设计表中「sheetPath 复用 workbookSheets、itemsOf/PAGE 收敛、apiOf+凭据分支去重、
   sync/push 前奏」四项无执行记录亦无不采纳记录（与 013 §一.2 批评过的 M2.5 静默遗漏同型），本轮补做或补记。
3. **token 精简**：team 段中「bot 审查三轮规则 / 审查线程处置 / 评审者记功流程」约 5.5k 字符低频内容每请求
   注入两角色，复用 013 N1.1 的 admission 迁技能模式按需进入上下文。
4. **配置面诚实性**：`models.utility` 为 M1 半实现（面板可配置可保存、无任何路由消费点）——按「清除冗余设计」
   删除；retro 聚合 `revisions` 字段因 SQL 缺列对 by=model/stage 永远为空。

不考虑数据迁移与旧数据兼容（沿用 012 决策 1；SCHEMA 保持 15，本轮不动存储结构）。

### R1 LLM 连续性修复（行为批）

| # | 内容 | 语义 |
|---|---|---|
| 1.1 | **transcript 分页与截断标记**：`events()` 请求 `maxMessages: 200` 并消费 `hasMore`——超窗时 transcript 头部带 `older_events: true` 与说明行，`message/<n>` 索引与 transcript 同源同窗；接线 `read.signal` | 长工单不再静默截断：模型明确知道存在更早事件（>200 条时可另读，宿主 `beforeSeq` 可用则提示指针）；默认窗口 50→200 |
| 1.2 | **usage 分页修复**：主会话分支改 `recent(offset + count).slice(offset)` | `orchestrator_read usage` 翻页不再重复读最新一页 |
| 1.3 | **飞书 HTTP 超时**：`TokenManager.token()` 与 `httpTransport` 两处 fetch、`feishu-credentials/probe.ts` 两个探测 fetch 补 `AbortSignal.any([signal, AbortSignal.timeout(30_000)])`；`FeishuImApi.messages` 的 `options.signal` 死参接线（两实现真正消费）或删除 | 单个半开连接 30s 失败进入既有退避/死信通道，不再无限期冻结 limit=1 的回写/轮询串行通道 |
| 1.4 | **retro `revisions` 修 SQL**：SELECT 补 `MIN/MAX(CAST(promptRevision AS INTEGER)) AS minRev/maxRev`，by=model/stage 桶返回真实修订范围；测试补 by=model 断言 | 「功能声称有、实际永远空」的承诺字段落地 |
| 1.5 | **work.md 提示词-schema 对账**：`orchestrator_report` 无 `pr_number` 参数（strict schema 会拒绝），改写为「PR 实际编号与 URL 写进 summary」；删除不可验证的「宿主可恢复缺失关联」句 | 模型首次报告 PR 不再被 schema 拒绝打断一步 |
| 1.6 | **会话重建续作说明**：worker 会话被外部删除重建时，注入一条 `session-rebuilt:<ticketId>` 幂等说明（指向 `ticket/<id>/assignment` 与 `inputs` 自读资源） | 重建后的 worker 知道去哪找回原始任务上下文，而不是只见新输入 |
| 1.7 | **UsageMeter 内存治理**：`requests` 条目在 `assistant/message` 消费后删除（重试会重写同键）；`softNotified` 在工单已结束时惰性清除 | 主会话长跑不再每 turn:step 漏一条；软档集合不随历史工单无界增长 |
| 1.8 | **LLM 友好错误微修**：评估 FINISHED 文案补「重跑 orchestrator_eval 载入当前评估」；`Unknown or inaccessible thread` 补 thread key 形态示例 | 错误即纠错指引 |

## 三、明确不采纳（避免过度收敛 / 待实测）

- **time-context / agent-instructions 预设行（P2/P3）**：担心 time-context 每分钟变化打掉 provider 端 prompt cache。宿主插件不在仓内、`dsh-system-prompt` 源码显示易变内容设计上走 dynamic context（历史快照）而非系统提示词段；router 预设 `complete: true` 只替换 sections、保留 contexts。**需真机按 usage 表 cacheReadTokens 实测后再动**，本轮不猜测性修改。
- **scheduler scan/tick 骨架合并**：两处轮询语义刻意不同步（scan 等全部轮询完成、tick 只投递），合并需保住该差异，结构漂移收益 < 风险。
- **worker 的 communication 角色化精简投影**：TEAM_SECTIONS 三段共享是 011 评审确认的团队契约，按角色拆分需改覆盖面语义，超出本轮。
- **relay/notice 死信补主会话告警**：有序死信已有面板健康可见性与人工重放；旁路告警有「relay 本身坏掉时谁投递」的鸡生蛋问题，待真机确认需要性。
- **git basic 头 3 行跨模块抽取**（sync.ts/probe.ts）：收益低于跨域耦合。
- **feishuView/historyView 参数化、readWikiTasks/syncCode 深嵌套拆分、tick 二次 settle、rotate CAS、ensureTaskFile 原子写**：语义有差 / 纯阅读负荷 / 防御性保留 / 单管理员场景 / 已有可读错误暴露——维持现状。
- **同文件使用却 export 的符号私有化**：沿用 013 §三第 4 条。

## 四、风险与对策

| 风险 | 对策 |
|---|---|
| review 迁技能改变 worker 审查处置行为 | 迁移逐字搬运 + 原文留强指引；`skill/review` 可团队覆盖；prompts/cards 相关测试全量回归并新增技能名单断言 |
| transcript 窗口 50→200 改变读取成本 | 上限仍是受控常数；TextCache 缓存不变（事件未变期间零重拉）；`older_events` 只是头部标记 |
| 飞书 30s 超时误伤慢接口 | 分页循环已有 200 页上限；30s 覆盖单次调用，CLI 路径 commandTimeoutMs=90s 不变；超时错误进入既有语义族分类（unreachable） |
| utility 删除使旧设置快照校验失败 | 决策 1/2：不考虑迁移与兼容；`.strict()` 拒绝即预期 |
| locale/导出删除漏改引用 | 全部结论已全仓 grep 固化；每批 `pnpm check`（typecheck 先拦截） |
| CRLF 陷阱 | 只用 Edit 局部替换；新文件一律 LF；提交前抽查 diff 行数 |
